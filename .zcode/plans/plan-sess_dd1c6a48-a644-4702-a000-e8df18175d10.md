# node 统一装配 + stage 派发注册表化（Phase A）

## 定位

用户目标态：worker/front 是 workflow 编排中的 node，统一配备提示词、工具、skills。
按已定决策链（奥卡姆 D1 修订版 + 触发架构步 1-3 已落地 + 昨日四 worker 工具对等已落地），本次切第一刀：

**Phase A（本计划）**：节点四件套统一装配（prompt 已就位 / MCP 已就位 / service_tools 已就位 / **skills 新做**）+ stage 派发注册表化（杀 front/worker 硬编码，新节点类型=一行注册）。
**Phase B（后续会话）**：pipelines 有序编排列表（`dm: [gate, triage, worker, deliver]`）——碰 service 主循环，风险面大，单独开盘。

统一粒度裁定：**agent 配置层**（options 声明，与 mcp_catalog 同构），front/worker 各自声明各自的能力面，preset 只做槽位组合。理由：与奥卡姆"分诊降为可选槽位"方向一致，避免 read_only front 被迫挂重工具。

## 改动清单

### 1. skills 统一挂载（核心新功能）

**配置面**：agent profile 新增 `options.skills: ["name", ...]`，引用 config.json 顶层 `skills` 池（现有 {name: path} 映射，保持向后兼容——现有 3 个 prompt 路径变量注入不动）。

**装配面**：`runtime.py` 新增 `_prepare_skills(profile, session_dir)` → 返回 skill 列表，四协议分流到原生通道（侦察已证实四家全有原生机制）：
- **pi**：`runners/pi.py command()` 为每个 skill 追加 `--skill <path>` flag（与 extensions 白名单正交，pi 文档实证）
- **dsh**：session 级动态生成 patch yml（新函数 `_generate_dsh_patch`）：skills 段用 `dsh-skill-filesystem` 插件 `customSkillDirs: [<session_dir>/skills]` + `includeDefaultRoots: false`（防 worktree 的 .agents/skills 串入）；**同时把现手写 dws-worker.patch.yml 的 MCP 段收编为动态生成**（模型层 provider 段保留静态文件）。`options.dsh_patches` 语义变为"用户附加 patch"，追加在生成的 patch 之后
- **codex**：worker 也走 per-session CODEX_HOME（现在只有 front 走，顺带杀 runtime.py:979 一处硬编码）；skill symlink 进 `<session>/codex-home/skills/`
- **claude**：session 级 `<session_dir>/claude-plugin/skills/` 放 skill symlink，`--plugin-dir <session_dir>/claude-plugin` 挂载（session-only，claude 无路径 flag，plugin-dir 是唯一按次通道；实现时先验证 plugin 目录结构要求）

**prompt 面**：`_prompt_variables` 注入 `{{skills}}` 清单变量（名字+一句话描述），各 worker 模板可引用。

### 2. StageHandler 注册表（杀 11 处硬编码）

- 新文件 `src/dws_dm_agent/stages.py`：`STAGE_HANDLERS: dict[str, StageHandler]` 注册表。`StageHandler` 接口 = 一个 async 入口 + 能力声明（read_only 期望、escalate 挂载、worktree、codex 隔离 home）
- `front` handler = 抽取 service.py:1388 的 front 路由段（gate 后只读处理→escalate/直答）
- `worker` handler = `_run_agent` 主路径调用点
- 新节点类型 = 写一个 handler + 注册表加一行 + preset 加槽位，service 主干零分叉
- 派发点改查注册表；worktree/escalate/codex-home 跟 handler 能力声明走，不再比 stage 名（runtime.py:974/979/1020 三处 + service.py 四处）
- **dashboard**：三处 `("front", "worker")` 循环（dashboard.py:277/433/509）改读 active preset 的 stage 键，面板可编辑任意 node
- **board.js**：PHASES 保留（phase 是处理阶段语义，与 node 名解耦），但 phaseLabel 单点化顺带做（board.js 改读 runtime.json 已有的 phaseLabel，对应审计 3.4）

### 3. config 迁移 + 测试

- config.json / config.example.json：各 worker profile 加 `options.skills`（首批：humanizer_zh、answer_me_with_html——即现有 prompt 路径引用的这两个，升级为原生挂载；front 不挂）
- 新测试：`tests/test_stage_registry.py`（派发注册表 + 新类型注册）+ `tests/test_skills_provision.py`（四协议装配形态，模型抄 test_dws_tools_mcp.py）
- 全套 pytest + 四 preset from_config 启动校验 + prepare 级装配验证（skills flag/patch/symlink 落盘）
- 真模型 E2E：dsh 渠道跑一轮带 skill 的面板轮（verify_launch.py 隔离实例）

# 会议/谈话 AI 助手设计（v6，2026-11-15）

状态：设计稿，未拍板。v5 五轮讨论收敛 + v6 首份真实会议转写（2h27m/5人/1349块）验证修订。

## 1. 定位与判据

给 dws-chat-agent（PROJECT D.I.A.M.O.N.D.，本机运行的钉钉 agent）新增音频对话通道，使其成为会议/谈话 AI 助手。

不是转写工具。判据：

- **会中**：对方事实断言/新需求/风险承诺出现时，我在下一轮发言前拿到核实结果（turn 完成到提示 P50≤16s）。
- **会后**：它替我完成我本来要做的验证与整理，每条结论可追溯到原文证据。
- **跨会话**：承诺不丢、矛盾被点名、集体盲区被结构化暴露。

适用场景：会议、需求沟通、私聊、想法交流。场景参数化——想法交流不开承诺账本，私聊不开红队。

## 2. 第一性原理：会议 = 分布式一致性协议

各方脑内世界模型不一致（状态分歧），对话是消息交换，试图向同一版本收敛；决策 = 分歧收敛时刻；任务/承诺 = 协议副作用（对未来的状态转移指令）；分歧未决 = 各方状态不一致且无人知道；transcript = 协议日志。

推论——助手的三重身份：

| 身份 | 对应能力 | 触发时机 |
|---|---|---|
| 协议审计者 | 承诺账本、对账、矛盾检测 | 会前注入 / 会后对账 / 后台追踪 |
| 协议外行动代理 | spawn worker 会中试验（spike/对齐/风险/数字） | 会中 |
| 协议外批判者 | 假设登记、红队审查、危险模式监测 | 会后 / 触发式 / 后台 |

## 3. 总架构

```
L0 采集      钉钉文件上传(V0兜底) / 电脑loopback(V1: ScreenCaptureKit/WASAPI)
L1 turn检测  VAD切边界 + 声纹标身份 + 合并规则 + 30s截断
L2 转写      FunASR 段级批处理(自部署, 数据不出本机)
L3 消息适配  turn → {speaker, text, t0, t1, type} 为一条 message
L4 会话层    dws agent 现有: per-conversation queue + serial lock
             + stabilize/merge + steering + watch轮询框架
L5 智能层    会中: 自主响应策略 + spawn worker + 代码对齐提示
             会后(终结钩子): 提取 + 交叉验证 + 风险深评 + demo信号
                           + 澄清队列 + 假设登记 + 账本对账
             跨会话(后台/触发): 账本追踪 + 红队 + 危险模式监测
L6 交付      钉钉卡片(结论+证据+纠正入口+澄清队列) / 手机推送
L7 评估      金标准集 / 回放回归 / 延迟指标 / 抽查校准
```

核心架构决策：**不为会议建独立管线**。会议 = 又一个消息通道；turn = 消息；录音会话 = 一个 conversation。音频通道复用 dws agent 全套消息机制（queue、串行锁、聚合、steering、卡片、replay）。

## 4. 采集与 turn 检测（L0–L1）

### turn 事件驱动切片（非固定墙钟切片）

一条消息 = 一个说话人的一轮完整发言，与聊天消息语义同构。

```
VAD(静音检测)      切边界: 500-800ms 静音 = turn 结束（主刀）
声纹(embedding)    标身份: 段 embedding 与注册库比对 / 在线聚类
                  合并判据: 间隔<2s 且同 speaker → 合并一条
30s 截断           单 turn 超长强制切，防独白阻塞
```

边界情况规则：

- 短语气词（"嗯""对"，<1.5s）→ 标 backchannel，不单独成消息，挂下一 turn 上下文（附和本身是信号）。
- 打断（overlap）→ 重叠段归主导方，打断点记 timestamp。
- 咳嗽/环境音 → VAD 能量门过滤。
- 冷启动无注册声纹 → 在线聚类 speaker-1/2/3，用户纠正一次 → 绑定身份回填。

### 延迟预算（turn 完成到提示）

```
turn 结束确认(静音)   0.5-0.8s
声纹标注(本地小模型)  <0.5s
ASR 批处理该 turn     2-5s（段短）
队列+pipeline         3-10s
──────────────────────────
合计                  6-16s
```

目标 = 「下一轮发言前拿到」，不是同声传译级。

### 身份解析（多源融合，声纹只是证据之一）

```
1. 声纹库: 自己(必注册) + 常聊的人(逐步沉淀)
2. 会议软件参会名单: 钉钉/腾讯会议 API → 候选集
3. 日历: 会议主题+受邀人 → 先验
4. LLM 从内容猜: "张总你看这个排期" → 线索
5. 用户纠正: 卡片点一下 → 回写声纹库（越用越准）
```

线下私聊场景 2/3 缺失，声纹是唯一硬证据。

## 5. 会话层复用清单（L4，零新建）

```
per-conversation queue + serial lock   turn 流天然排队、串行
stabilize/merge                        连续 turn 聚合上下文
steering (Codex turn/steer, Pi steer)  会中查询 = steer 进 live session
thinking card 增量更新                 会中提示
钉钉推送                               手机端提示通道（会中共享屏幕时唯一安全通道）
watch 轮询框架                         音频切片器 = 新 watch 源
replay 回放                            固定录音回放 = 回归测试
```

关键消解：**被动监听的触发时机难题不需要外部触发器**。agent 在消息流内自主判断——背景讨论只更新上下文（静默），事实断言/新需求/承诺信号出声。与它处理钉钉消息流的行为模型完全一致。

## 6. 会中智能（L5a）

### 三类自动响应

```
事实断言 → 核实: "你们支持X吧" "上次说好Y"
    查 repo/文档/上次会话 → 支持/不支持/部分/与上次矛盾
新需求 → 可行性粗判: "能不能做一个Z"
    查 repo 结构/API 面 → "看起来可行, 依赖W" 级别（会中不深评）
承诺/同意 → 风险: 说了"行/没问题"
    查排期/上次承诺/依赖方 → "上次同问题承诺未兑现" "本周无档期"
```

会中只粗判+证据指针，深评留给会后。会中拿不到完整上下文，装作能深评 = 错误答案比晚答案更糟。

### 静默纪律（产品风险点，需真实会议调）

哪些信号值得打断（对方在等答复的核实）、哪些只记录（背景性提及）——分级策略是验收项。

### spawn worker 会中试验

触发：主动 steer（"试试X可行吗"）；或 agent 检测到可验证假设 → 建议 spawn，用户确认。

四类任务：

| 类型 | 内容 |
|---|---|
| spike 原型 | 最小代码验证想法，沙箱写，不动主干 |
| 代码对齐 | 「会上讨论的系统」vs「真实 repo」差异审计；人们脑内模型通常过期，"你说的模块上月已重构掉"是会中最高价值提示 |
| 风险探测 | 依赖/兼容/性能预估 |
| 数字验证 | 会上拍的数字 vs 实测 benchmark |

约束：会中 worker 只读+沙箱写；时间盒 10-15min；结果 3 行摘要+证据推钉钉；散会未完转入会后深评队列。

本质：把验证延迟从「散会后几天」压到「会议进行中」。很多会死于"回去验证一下再定"——验证在会内完成，会直接收敛到决策。

## 7. 会后智能（L5b，session 终结钩子）

会议结束标记：手动停录 / 静默 10 分钟 / 日历到点。同一 conversation，终结时升级处理深度——不是第二套系统。

```
1. 提取四类(每条带原文引用+说话人+置信度):
   action_items: 承诺/待办(谁、做什么、何时)
   decisions:    已定结论(防"会上说好了事后没人认")
   open_questions: 待澄清点(需求沟通核心产物)
   ideas:        原始捕获(不加工, 原文+出处)
2. 自主验证(核心, 区分助手与工具):
   每条核对 repo/Jira/历史会话/文档
   → 新 / 已存在 / 与历史矛盾 / 需澄清 + 证据链
3. 风险深评: 可行性、依赖、被挑战假设
4. demo 判断: 需求成熟度信号(边界清晰/问集成/问排期/决策人出现/竞品讨论)
   +原文证据, 达阈值才输出(规则+LLM混合, 阈值可调)
5. 澄清队列: 无法验证或歧义的 → "要问我的问题", 回复后并入
6. 假设登记(盲区层1): 提取本次会议隐含前提, 分级(致命/重要/次要), 累积登记簿
7. 账本对账: 上次承诺兑现? 上次问题被回答? 矛盾点名
```

## 8. 跨会话智能（L5c）

### 承诺账本（需求1核心，壁垒所在）

```
每条: {内容, 谁, 提出@会A, 确认@会B?, 截止, 状态: open/执行/兑现/违约/失效}
会前钩子: 自动注入「本群人相关未兑现承诺+未决问题」→ 会议带账本开场
会后钩子: 新承诺入账 + 对账
后台: 违约检测追踪
```

单场纪要无壁垒，跨会议状态机重建有。冷启动空转（前几周无历史）正常，先攒。

### 红队审查（盲区层2，触发式）

触发：同一主题第 3 次会未收敛 / 反复改同一模块 / 风险信号累积。

fresh context 子代理（刻意不带讨论历史，防同化）五问：

```
Q1 从零重写还会选这个架构吗? 不会, 差在哪?
Q2 这是在解决问题还是在转移问题?
Q3 同类尝试历史死法? 我们有哪个征兆?
Q4 项目的停机条件是什么? 现在到了吗?
Q5 最聪明的不看好者会说什么?
```

规则：质疑必须引用 repo/账本具体事实，无证据的丢弃——防"正确的废话"。

### 危险模式监测（盲区层3，客观信号）

```
同一问题第N次会议重现     重复讨论 = 错误层面解决
方案复杂度单调上升         每次都在加补丁 = 本质问题征兆
承诺-兑现差扩大            团队自欺信号
关键主题长期无人提及       集体回避区
```

全客观可计算（账本+主题聚类即有数据），不依赖 LLM 判断力，是盲区三层中最可操作的一层。

## 9. 交付（L6）

每场对话一张钉钉卡片：

```
[摘要3行] [参会人: 已识别/未识别]
[action_items / decisions / open_questions / ideas]
[demo信号: 有/无+证据] [对账结果: 上次承诺状态]
[澄清队列] [纠正入口: 说话人标错点一下]
```

会中提示走钉钉私聊推手机（共享屏幕时唯一安全通道）；桌面悬浮窗可选。

## 10. 数据与存储（新增）

```
声纹库          注册 embedding + 纠正回填
transcript 存储 会议全文(带speaker/时间戳), 会后深评输入
承诺账本        跨会议持久化
假设登记簿      累积
事实源索引      repo 符号索引 / 历史会话摘要缓存(会中查询预热, 临时grep太慢)
```

## 11. 合规与约束

- ASR 自部署（FunASR），对话数据不出本机。
- 录音需告知参会方（PIPL）；启动时系统级提示；transcript 存储加密。
- 会中 worker 只读+沙箱。

## 12. 验收（先于实现）

用 5-10 段真实历史录音建金标准，先定数字再写代码：

```
任务提取          P≥0.9 / R≥0.7（人工标注 vs 助手产出）
验证判定          抽查准确率≥80%
会中延迟          turn完成到提示 P50≤16s
信号触发          漏报率/误报率分开测
静默纪律          打扰率人工复核
账本对账          准确率抽查≥80%
红队产出          可行动率≥50%（引用不到事实的丢弃）
危险模式信号      人工复核有效率≥70%
回放回归          固定录音集, 改 prompt/模型必须跑（音频回放=消息重放, 复用 replay）
WER/DER          jiwer / pyannote metrics, 纯客观
```

## 13. 路线图

```
V0    钉钉发音频文件 → 一次性灌入 conversation → 会后管线全跑通
V1    电脑 loopback + turn 检测器 + 会中静默/出声策略
V1.5  spawn worker 会中试验 + steer 查询 + 高优先信号响应
V2    账本/红队/危险模式(跨会话三件) + 切片参数自适应 + 韵律信号(犹豫/打断)
```

新代码收敛到四件：turn 检测器（VAD+声纹+合并规则）、ASR 适配器、终结钩子、跨会话三件。其余跑在现有消息管线上。

## 14. 诚实边界

- 红队产出容易泛泛——验收管住（可行动率），引用不到具体事实的丢弃。
- 账本冷启动空转，正常。
- 盲区识别没有银弹——助手自己也是 LLM。设计给的是结构化暴露+视角隔离+客观信号，不保证发现一切。
- 切片轮询延迟 6-16s，快节奏交锋场景不够，V2 参数自适应缓解，架构不变。

## 16. v6 修订（真实数据验证，2026-11-15）

用一份真实会议转写（2h27m、5 说话人、1349 块、13 话题）作为测试集，三个独立子代理分别做提取/盲区红队/设计验证。数据支持四个骨架判断（事件驱动切片、会议=消息通道、会中粗判+会后深评、静默纪律是最大风险），打脸三个未写入文档的暗层假设。修订如下（均不动架构）：

### P0-1 ASR 实体归一化层（新增 L2.5）

实测：错字率字数层面不高，但 100% 聚中在产品名/技术名/人名，且同一实体多种写法（智客→刺客/自客/Zik；APISIX→ABS；ConfigMap→Kafka Map；SQL→circle×5；fallback→for back/佛拜克），另有幻觉英文插入句（"Put that down"）。后果：承诺账本实体断裂、会中核实检索 miss、验证给出错误结论。WER 对此失明（字错率低、实体错配率高）。

修订：L2 FunASR 加 hotwords（会前从事实源索引自动生成：repo 符号/产品名/常提人名）；L3 前加专名归一化（同音/编辑距离归并到词表）+幻觉句过滤；验收增加「专名准确率」独立指标。

### P0-2 turn ≠ message，聚合窗降速阀

实测：块到达速率 ~9 块/分钟（中位 4s、30% 碎块≤12字、说话人切换 8 次/分钟），而单条处理预算 6-16s——字面实现「turn=一条消息」必打爆串行管线，且多数碎块无响应价值。

修订：turn（L1 采集单元）与 message（进 L4 管线单元）解耦；进 conversation 前按静默聚合窗（15-30s）或话题稳定窗聚合；stabilize/merge 升级为「降速阀+聚合」双职能；聚合窗参数入回放回归。

### P0-3 静默纪律初始策略反转

实测：2.5h 内「长得像三类信号」的句子每分钟数条，真正值得会中打扰的 ≤3 处，其中 2 处人类当场已自我纠正。可打扰率约 1 次/小时。初始分级偏松=2.5h 弹几十条=产品被关掉。

修订：初始默认全静默，仅放开「与本会前文/账本/仓库直接矛盾」类（实测唯一高价值命中：ES 依赖"全删"vs 13 分钟后"全上 ES"，矛盾检测窗口须跨 ≥15 分钟）；验收加绝对打扰上限（2h 会议 ≤2 次）。

### P1 修订

- **归属错误**（P1-4）：实测 diarization 有串扰（上句尾巴被切进下一 speaker 块）。验收加归属错误抽查；纠正入口加「此句归属错误」粒度（细于换 speaker 标签）。
- **话题模型**（P1-5）：实测 13 话题、3 次显式回跳（"还是回到知识库本身"）、同一决策跨 88 分钟三段演进（重写→推翻重来+连带3.0+派人）。线性 stabilize/merge 与回跳结构错配；2.5h/1349 块单次深评必超限。修订：终结钩子按话题分片并行深评+汇总；提取器加「决策演进合并」规则（同决策多次表达合并为 1 条带演进轨迹，防自己的矛盾检测误报自己）。
- **账本形态**（P1-6）：真实派活多为「有 owner 无期限无验收」（"李川你们这边弄一下"）。账本支持 no-deadline 条目，区分「无限期未启动」与「逾期」；提取保留指代消解原文锚点。
- **身份解析优先级**（§4 修订）：线下会议「会议软件参会名单/日历」证据源不存在，且说话人从不自报姓名、提及的人名全是第三方。优先级改为：声纹（跨会稳定匿名 ID+角色画像沉淀）> 内容角色画像 > 名单/日历（仅线上）。

### P2 修订

- 事实源可达性分级：本机 repo / 外部系统不可达 / 公开事实。不可达时「核实」降级为「登记待问」，不装作能深评（顾问会议讨论的是对方公司代码）。「数字验证」类 spawn worker 标注事实源前提，会中不可达则归会后。
